# 委託標記為 6 個 base62 字元：1 字元 node、5 字元雜湊

委託標記寫進券商的 `custom_field`，固定 6 個 base62 字元（`0-9A-Za-z`）：第 1 字元是 node 識別，後 5 字元是 client order id 的雜湊。官方 server 1.7.6 對 `custom_field` 的上限正好是 6 字元，超過即在下單時同步拒絕；base62 的邊界字元在委託回報中原樣帶回、大小寫不變（`docs/official-server-contract.md` §2 的 10/1 紀錄），因此 ADR-0004 的候選配置不需調整即可定案，並取代 ADR-0004。

## Considered Options

- **5 字元以上的流水號取代雜湊**：同一交易日內不會碰撞，但認領時要有持久化的「標記 → client order id」對照，重啟後的認領因而依賴這份狀態；雜湊可由快取中已知的 client order id 重算，不需另存。
- **不保留 node 字元，6 字元全作雜湊**：碰撞空間較大，但出現第二個 node 時要改編碼，在途委託會無法認領（ADR-0004 的理由）。

## Consequences

- 雜湊空間有限，同一交易日內兩張委託可能得到同一個標記；認領時標記相符只算候選，須再比對商品、方向、數量與價格，對不上就不認領並記錄。
- node 字元在單一 node 時固定為一個值；多 node 的分配規則等第二個 node 出現時再定。
- 編碼在第一張真實委託送出前即定案，之後變更須同時支援新舊兩種標記直到舊委託結清。
